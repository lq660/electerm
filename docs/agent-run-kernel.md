# AgentRun 内核

2026-09-08 coder(lq): 独立执行内核已接入 AI Shell，补齐完成核验、有限续查、完成收口与执行隔离。

## 设计决定

仅调整提示词无法保证任务完成，也不能安全中断已发送的命令。因此由独立内核统一决定完成和停止，模型负责选择下一步、解释证据；执行适配器负责真实结果和取消。
不增加 Nginx、Docker 等命令专用完成规则，不从普通回复或终端输出中提取命令执行。既有策略模块仍用于提示词、参数校验和风险判断，不再决定最终完成。
代价是候选结论需要额外一次模型核验，增加请求延迟和费用；确定性的引用检查只能确保引文来自真实观察，不能代替语义正确性评估。

## 模块职责

- `agent-run.js`：持有单次任务的上下文、模型循环、工具调用、审批等待、进展判断、结束状态与停止检查。不依赖 window、store、Electron 或具体模型供应商。
- `agent-verification.js`：构建有界执行观察和核验请求，校验结论结构、证据引用和后台完成状态。
- `agent-task-wait.js`：后台状态限时等待，避免立即反复查询消耗轮次。
- `agent-policy.js`：提供提示词、命令参数和风险策略；旧结果辅助函数保留兼容，但不作为内核完成门槛。
- `agent.js`：应用适配层，提供 IPC 模型请求、实际工具执行、审批交互、历史记录更新；保留按终端排队与运行计数。
- `agent-tools.js`：将工具调用和取消信号映射到实际执行通道。
- `src/app/server/agent-command-execution.js`：管理独立 SSH exec 通道或本地进程组，提供输出、真实退出码、后台快照和按执行 ID 取消。

## 接口

`createAgentRun({ requestModel, requestVerification, executeTool, requestApproval, onUpdate })`
返回 `start(task, config, abortRef, onStreaming)` 和 `stop()`。
每个实例只能启动一次；不同实例的上下文和停止状态互不影响。
`start` 返回包含 response、toolCalls、agentRuntime 和 agentEvents 的任务快照。
更新通过 onUpdate 推送，应用负责持久化和显示。

requestModel 接收消息、配置和 signal；requestVerification 接收目标、上下文、候选回复和执行观察，并返回下面的结论契约。executeTool 接收工具名、参数以及含 runId、executionId、signal、onCleanup 的执行上下文，可返回字符串或 JSON 对象。requestApproval 接收运行范围内唯一的 approvalId 和停止状态，返回 approved/reason。
测试和实际应用使用同一入口，不复制执行循环。

## 四项行为契约

1. **有证据才完成。** 候选回复不直接成为最终答案。核验器返回 status（complete/continue/blocked）、answer、reason、evidence（toolCallId/quote）和 scope（execution/conversation）。内核拒绝空结论、虚构引用、未匹配引文及运行中/取消/超时结果；后台任务未结束不能完成。仅纯会话且没有执行观察可免执行证据。
2. **缺证据就补查。** 核验缺失项返回主模型，要求直接调用工具。每轮最多执行一个 shell 命令，跳过项也补齐工具协议结果；重复动作有次数限制，不无限重试或只输出继续承诺。
3. **已完成就收口。** 证据充分时核验器直接给出简洁结论，即使候选回复只是计划话术也无需再执行。未通过核验则不标成功；多次无进展或达到上限给出明确未完成原因。
4. **停止按运行隔离。** 手工停止使模型、工具和审批等待立即退出，拒绝迟到结果。取消模型请求使用独立请求 ID；取消命令使用会话和 executionId，仅作用于拥有的 SSH 通道/本地进程组，不往可见终端发送中断键，不关闭共享 SSH 连接。删除审批 ID 同样绑定运行，避免多会话串用。

## 等待和失败边界

- 总模型循环上限 30 轮；连续无动作核验失败最多 3 次，连续无新证据最多 3 轮。重复低风险动作最多 2 次，其他动作最多 1 次；后台监控不受动作重复限制。
- 后台状态默认等待 10 秒，最多 30 秒，每秒最多查询一次；正在等待运行中任务不按无进展处理，但仍受总轮次限制。
- 前台命令默认 45 秒，最多 120 秒；后台执行通道硬超时 12 小时，不代表内核承诺持续运行 12 小时。运行完成、阻塞或手工停止都会取消其仍持有的后台执行。
- 模型请求失败、工具异常、审批拒绝和无法核验均不得伪装成成功。缺失退出码保留 null，不补成 0。
- 观察保留有界头尾内容并标记截断；详细工具输出保留在可展开执行记录，最终回复仅展示核验后的结论。

## 已知限制

语义核验使用当前配置的模型，不是独立事实预言器；真实模型仍可能错误理解目标或错误关联证据。引用校验不等于证明结论的每个语义断言正确。
队列和历史持久化目前由应用适配层管理。
SSH 取消会请求终止并关闭独立通道，但远程进程可能忽略信号或已派生脱离通道的进程，因此不声称已经确认所有远程进程退出，也不撤销已执行的修改。
没有 shell 能力的会话不能通过此通道执行 shell；Windows 本地独立命令仍按现有能力限制处理。

## 验证

完整回归：`npm run test-unit-ci`；生产前端构建：`npm run build`。

定向验收覆盖：

- agent-run / agent-verification：无浏览器执行、工具协议配对、仅路径证据不足时补查、证据充分后停止、虚假引用拦截。
- agent-run-acceptance：变更后核验、无进展有界退出、停止模型/工具/核验/审批等待、并发运行隔离和删除审批 ID 隔离。
- agent-command-cancel：真实本地进程组退出码及取消、模拟 SSH 独立通道取消、迟到通道、后台实时输出。
- agent-task-wait：限时等待、无忙循环、取消等待、传输错误不当成功。
- agent-provider-cancel：真实模型请求适配器连接本地临时 HTTP 服务，验证取消连接及独立请求不受影响；不使用真实密钥。
- agent-session-routing：实际会话路由接通本地执行器，验证后台启动/状态/取消和无能力错误。

以上不包含真实模型与生产服务器端到端成功率，也不替代桌面 UI 人工验收；验收报告必须区分自动化契约验证与这些尚未进行的实测。
